## How it works

Each step picks an action and a random person (parent, student or the agent) with random arguments: honest use
(draft, sign with the phone's passkey, send with an Idempotency-Key, let days pass so transfers land and the autopilot
runs, write and sign a family mandate) mixed with attacks. After **every** step the invariants below are checked
against the real state: the bank's double-entry books, the drafts and their approvals, and the hash-chained log.

| Invariant | Rule | Violations |
|---|---|---|
| `INV_NO_UNAUTHORIZED_TRANSFER` | No money moved without people's passkey approval or a signed mandate | 0 |
| `INV_NO_UNVERIFIED_PAYEE` | No money went to an account that is not allow-listed and verified | 0 |
| `INV_AGENT_PRIVILEGE_CEILING` | The agent never approved, signed, or executed outside a mandate | 0 |
| `INV_TWO_PERSON_RULE` | Every payment of ৳1,00,000 or more had both the parent and the student | 0 |
| `INV_PASSKEY_BINDING` | Every approval behind a payment is a verified passkey signature over that exact draft | 0 |
| `INV_BOOKS_BALANCED` | Double-entry books balanced in each currency and reconciled with every account | 0 |
| `INV_EXACTLY_ONCE` | No payment was booked twice, whatever was retried or replayed | 0 |
| `INV_TAINTED_AMOUNT_BLOCKED` | The agent never got a payable draft for an amount planted in outside text | 0 |
| `INV_AUDIT_HASH_CHAIN` | The hash-chained audit log stayed unbroken | 0 |

## Does the fuzzer have teeth? Deliberate bugs

A "0 violations" result only means something if the fuzzer would have caught a bug. Each mutant breaks one rule on
purpose (only during its own run); the fuzzer must catch it.

| Mutant | The bug | Result |
|---|---|---|
| `double_booking` | Bug: the bank forgets which drafts it already booked, and a retried send of a paid draft books it again. | caught (step 166) |
| `plain_approvals_allowed` | Bug: people can approve without a passkey signature (the server stops checking). | caught (step 200) |
| `taint_check_off` | Bug: the payment sink stops looking at where the amount came from. | caught (step 18) |

## A real gap it found

The first run of this fuzzer found one: SMS that the inbox ignored as "not about money" were never labelled for
taint tracking, so an amount planted in such a message could reach a payment the agent drafted. Fixed by labelling
the amounts of all outside text at the door, before any filtering (`app/inbox/service.py`), with a regression test.
